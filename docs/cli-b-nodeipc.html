Reading the grid

Four columns, one edge each: the pill names the section once, the dots carry severity, the name is the capability class (or rule), and the locator is where it lives (namespace, or the trait count). Sub-rows leave the pill empty, so a section reads as a block. Signatures have no locator, so the rule name spans that column. When a section has nothing (no metrics here, no identity), it simply isn't drawn — no empty headers.

Evidence, reworked

Evidence is not forced into the capability columns anymore. It gets its own three columns — line, code (truncated with … , never wrapped), description — under a member header. So the proof scans as its own table: line numbers align right, the code forms one left edge, and the plain-English note forms another. This is the part of B you didn't like; this is the fix.

Everything here is grid-aligned rather than space-counted, which is how the real CLI will pad it. If this reads clean, it becomes --format terminal. The one open call: whether the risk gauge should also align its 0.40 … 0.97 to the grid's columns, or stay a free masthead element.
